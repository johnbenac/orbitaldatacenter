# Engine interface
`import {createSimulation} from './model.js'`; `createSimulation(design)` memoizes by object identity and returns `{at(t),window(start,duration,count=180),events(start,duration),mission(count=90),daySummary(start),modelNotes}`. Window and mission return arrays of flat numeric states, events arrays of `{id,type,label,start,end,station?}`. `at(t)` seconds since model epoch returns flat unit-suffixed state. Core fields `t, altitudeKm, orbitNumber, betaDeg, eclipse, station, stationECI, positionECI, velocityECI, sunECI, deployment, dishAzDeg, dishElDeg, windowAgeYears, solarKW, loadKW, batteryKWh, socPct, junctionK, radiatorK, queueGB, deliveredGB, goodputMbps, lineMbps, uplinkMbps, terminalKW, cmgKW, momentumNms, torqueNm, dragN, propellantKg, burn, desat, tokensPerSec, activeFraction`. ECI positions/velocities km and km/s. `station` is a name or null; `stationECI` is km or null. Extra fields documented by source. Times default to seconds, all GB/TB decimal. Detailed contact events are `type:'contact'`. Events predictably clipped at requested range only in display, stored start/end times ideally span the physical episode. `mission` is a representative-day reduced-order sweep with periodic checkpoint state, indicated in the output; detailed nearby windows integrate operational states. Model notes enumerate resolution and boundaries.
createSimulation takes sized hardware h from sizeDesign; also accepts flat input via sizeDesign. API extra keys include perigeeKm,apogeeKm,periodSec,rangeKm,elevationDeg,stationLatDeg,stationLonDeg,earthRotationRad,shadowSeconds (daySummary),generationKW (=solarKW),itKW,storageKW,pumpKW,chargeKW,dischargeKW,unmetKW,curtailedKW,batteryK,availableKWh,coolantK,coldPlateK,grossEmissionKW,absorbedKW,netRejectionKW,thermalMarginK,unloadTorqueNm,torqueXNm,torqueYNm,torqueZNm,magFieldUT,pointingErrorDeg,ramAreaM2,densityKgM3,dragImpulseNs,propellantUsedKg,fuelKg,oxidizerKg,tankFillPct,deliveredGB,uploadedGB,generatedGB,droppedGB,freeTB,prefillPerSec,perUserTps,goodputMbps,lineMbps,contact (boolean),groundLink ('Ka','Optical','S-band',null). modelNotes array of strings. daySummary returns {minSocPct,maxJunctionK,shadowSeconds,contactSeconds,contactCount,eclipseCount,deliveredGB,generatedGB,uploadedGB,peakQueueGB,maxLoadKW,unmetKWh,propellantUsedKg,...}. mission returns array with typical states plus minSocPct,maxJunctionK,peakQueueGB sampled in each representative day, and coarse projection flag.

Chronological verification is available as `await sim.runAudit(({days,totalDays})=>updateProgress(), {signal})`. Its result includes `annual`, `energyKWh`, `eventTotals`, `dayStats`, first operational crossing with slacks, `finalState` and whole-mission extrema. The same sim adopts the resulting daily checkpoints. The solar weather driver accepts `nominal` or `observed`; the latter replays monthly 2009–2019 NRC Canada F10.7 values via NOAA PSL, with monthly interpolation used as the daily proxy and neighboring months as the 81-day proxy. ECSS-E-ST-10-04C Rev.1 Table G-4 supplies the JB-2006 density envelope. Projected states use 90-day representative quadrature with a one-day fast-state spinup and continuous integration across each selected window. All reported lifetime totals preserve cumulative counters; `dayGeneratedGB`, `dayDeliveredGB` etc are named separately. `slewFraction`, `slewTorqueNm`, `slewMomentumNms`, `ramBody` and `orbitLost` are available on live snapshots.

`silhouette.js` builds the projected convex hull of the instrument bus and four wing and two radiator rectangles. It splits the integration line at every projected vertex and edge intersection, unions covered intervals, and tabulates directional samples at 5° for fast repeated evaluations. Partial deployment blends stowed and deployed reference areas. The pressure-center lever remains an editable assumption. The detailed radiator/core path uses one transient heat store with algebraic stage temperatures. RF, clear-sky optical and orbit propagation use the simplifying assumptions enumerated in `modelNotes`.

`textGeneratedGB`, `textDeliveredGB`, `textDroppedGB`, `textQueueGB`, `bulkQueueGB`, `bulkDeliveredGB`, `tokensDelivered`, `textGoodputMbps` and `bulkGoodputMbps` separate generated output text from initial backlog and bulk files. Text has first access to recorder writes and downlink slots. `commandDemandKbps`, `commandGoodputKbps`, `uplinkQueueMB`, `uplinkGeneratedMB`, `uplinkDroppedMB`, and `uploadedGB` track ground command generation, finite buffering and actual packet reception through a separately acquired S-band channel. `daySummary` and chronological annual rows include `tokensDelivered`, `textGeneratedGB`, `textDeliveredGB`, `textDroppedGB`, `bulkDeliveredGB`, `commandDroppedMB`, and `uploadedGB` for the interval. Mission plot samples retain cumulative values and use the `day` prefix for daily deltas. The interactive control set configures a fixed mission-wide operating policy.

## Guided flight and disposal

`sim.story(id)` returns one lazy chapter with its stable event ID, start, end, and preferred instant. `sim.story()` returns the ordered ten chapters. The first sixty days are integrated chronologically. A subsequent representative-day preview positions later events. A completed mission audit supplies chronological checkpoints for all dates. Short missions can lack a particular operational event. Such a chapter returns its searched interval and reason. Prelaunch integration runs at MET −3600 to −600 seconds, followed by the pad until liftoff. The rotating inferred pad and smooth kinematic loft join the insertion position and velocity at MET 540 seconds. Carrier stage performance and launch-complex selection are illustrative.

`sim.disposal()` returns the finite maneuver's ignition, cutoff and descending entry times in `start`, `cutoff` and `entry`. `requiredDv` is an impulsive vis-viva estimate in m/s, `paidDv` includes finite-burn losses, `usedKg` is actual propellant mass, and `goal` is targeted osculating perigee in km. The model schedules a burn near a late apogee inside the chosen mission horizon. Thrust opposes inertial velocity. RK4 advances position, velocity and decreasing wet mass. Guidance stops at the specified perigee and coasts to 120 km. A failed prospective maneuver inhibits ignition and supplies a reason. Normal reboost protects the larger of the entered disposal allocation or nominal required Δv, plus maneuver reserve and trapped residuals. Disposal can use the operational reserve, leaving the trapped residual. Compute stops and appendages stow before ignition. Beyond model termination, snapshots hold the last physical inventory. No atmospheric breakup, impact location or footprint is modeled.

The enclosure exchanges heat with the shared thermal node through the blanket and modeled seam conductance. The exterior radiative equilibrium receives directional direct light, albedo and Earth IR, averaged over the six bus sides. `enclosureLeakKW` is positive outward. `energyKWh.enclosureOutward` integrates this signed flux. The inner skin and participating frame add to `thermalCapacityKJK`.
